# 从训练演示到可解释的数学辅导项目

本轮基础工作：新增离线审计工具、逐题配对比较、验证集人工审阅模板、模型说明和实验计划。没有重新训练、消耗付费算力或改变原始评测文件。

## 当前证据

- 原始 Qwen 与 SFT 在同一 200 题测试集：23/200 → 48/200，自动数值正确率 +12.5 个百分点。新增确认正确 34 题，丢失确认正确 9 题；不能把全部提升解释为推理能力增强。
- SFT Adapter 与合并 SFT 在同一 100 题验证集：17 → 18，8 条回答变化；合并等价性仍需核查。
- 合并 SFT 与 DPO：均 18/100，6 条回答变化；没有发现数值正确率提升。
- DPO 的 50 条偏好验证记录上 eval_rewards/accuracies=0.92，表示相对参考策略的隐式奖励排序，不是数学解题准确率。
- 1000/100/200 条处理记录没有重复 ID、重复 family 或跨集合 family 重叠；不能排除语义近重复。

## 推荐功能主线

优先做“学生步骤纠错”，然后做“分级提示”，最后再加简单界面。

1. 学生步骤纠错：输入题目和学生解法，输出首个错误步骤、错误类型、原因和最小提示。重点错误包括审题、列式、计算、单位、推导跳步；正确解法需要有无错误对照。
2. 分级提示：先指出知识点，再给关键关系，学生主动请求后才给完整答案。评价提前泄露答案比例、提示正确率、步骤可执行性。
3. 数学工具校验：对明确算式用受限表达式计算器复核，显示校验通过/失败/无法检查。算式算对不证明列式符合题意，不可用标准答案反向修补模型输出。
4. 诊断与变式练习：基于已人工核验的题型模板和错因生成练习，再校验答案。新生成题不能未经审核作为测试集。

这些功能避免重复数据问答 Agent。第一轮只选一个主功能，不需要同时做 OCR、语音、多智能体。

## 人工必须承担的验收

### A. 审阅验证集错误（先做 30 条，再覆盖全部 100 条）

文件 reports/internship-audit-v1/human_review.valid.jsonl 已有题目、回答和参考值。
填写 reviewed、reference_correct、solution_correct、final_answer_correct、unit_correct、error_type、notes、reviewer。
布尔字段使用 true/false；不能确定时保持 null 并写明原因。单位不适用也用 null，备注“不适用”。
error_type 建议：question_or_reference / comprehension / formulation / arithmetic / unit / contradiction / format / other / none。
先独立解题再判断参考值；如果依赖 AI 草稿，仍要独立核验。验证集修订另存版本，保留旧答案和理由。
这些记录用于诊断与评测，不能回流训练。

### B. 新训练偏好对（与 A 分开）

只从训练池抽取至少 100 道题，保留模型实际错误回答；人工写出或核验 chosen，判断 rejected 确实较差。
记录来源 ID、family_id、错误类型、审核者、审核时间。优先使用真实列式/推理错误，不能只给答案加一个常数。
两种不同但都正确的解法不能随意标为优劣。建议复审随机 20 条，不确定的先剔除。
这一数量是起步预算，不保证模型提升。

### C. 纠错任务的验收标准

人工设计独立开发集，覆盖正确步骤和多种错误；记录首错位置与可接受提示。测试题应另外封存。
用“首错定位正确率、错误类型正确率、误报率、提示质量”评价，不能沿用最终数值准确率替代。
若没有用户研究，不能宣称提高学生成绩或学习效果。

### D. 学习与面试

亲自解释一条样本的 input_ids/labels、-100 掩码、LoRA 训练参数、DPO 参考策略、评测边界；亲手运行至少一次小实验并分析失败案例。
代码可由 AI 实现，但简历中必须区分复用的开源训练框架与你自己设计的数据、任务和实验。
