## 吞吐与时间

下表使用原配对测试，每个并发档12请求；TTFT为首段文本代理，TPOT为估算，单位ms。

| 并发 | Transformers token/s | vLLM token/s | 吞吐倍数 | TTFT近似 前→后(ms) | TPOT估算 前→后(ms/token) |
|---|---:|---:|---:|---:|---:|
|1|10.81|48.74|4.51x|90.74 → 79.92|93.87 → 16.78|
|2|9.78|56.03|5.73x|1861.38 → 344.40|103.76 → 16.24|
|4|11.09|54.20|4.89x|4832.45 → 956.84|90.04 → 16.90|

TPOT估算 = (请求结束时间 − 首段非空文本时间) / (重新分词后的输出token数 − 1)，先按请求计算再取中位数。首个文本块可能包含多个token，结束时间包含SSE收尾，因此不等同于引擎严格TPOT。原始输出tokens是重分词口径，不包括EOS。严格值需要上游token级时间戳或引擎原生指标，旧日志无法补回。

两个阶段分别在11月17日和11月19日运行，Windows Transformers与容器PyTorch/CUDA版本不同，且vLLM仅允许单活跃序列。改善属于当前部署栈实测，不把全部差异归因于某个单一优化，也不推断生产容量。

## 显存

原本地服务：PyTorch已分配0.93 GiB；历史整卡单次快照3094 MiB。vLLM补测：36次流式请求全部成功，整卡显存采样39次，采样最高2040 MiB。包含显示及其他进程。不是相同轮次、相同口径的双后端峰值，不计算显存节省百分比。

新增 deploy/vllm/metric_probe.py，可在已有网关运行时采集显存与流式性能，不停止任何服务：

```powershell
python deploy/vllm/metric_probe.py --base-url http://127.0.0.1:8000 --output reports/vllm-memory-new-run
```

如需同口径显存对照：先停止vLLM容器，独立启动Transformers网关8002，以同一脚本和相同负载采样；停止Transformers，再启动vLLM采样。固定背景GPU应用，另外记录空载显存；不要同时加载两份模型。原报告和已完成结果不应覆盖。

## Docker访问拒绝诊断

助手命令执行身份为同一Windows账号，但whoami /groups显示Low Mandatory Level，已拥有docker-users组。普通终端此前成功执行Docker控制命令，助手仍被Docker命名管道拒绝。最可能原因是助手的受限执行令牌/沙箱，并非缺少docker-users组；尚未在无沙箱环境中复验，不能声称已经解除。

需要用户操作：在当前聊天输入框附近的权限控件选择Full access（如可用），随后发消息让助手重新执行docker info验证。企业管理策略可能不允许该选项；此时保留由用户终端运行Docker脚本的方式。无需重复添加docker-users、关闭UAC或暴露未鉴权2375端口。

依据：[Docker Windows权限文档](https://docs.docker.com/desktop/setup/install/windows-permission-requirements/)、[OpenAI执行沙箱与权限说明](https://learn.chatgpt.com/docs/sandboxing.md)。
