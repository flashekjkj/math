# 第一轮实验检查与结论

## 已确认的流程

环境：Python 3.11，RTX3050 Laptop 4GB，Qwen2.5-0.5B-Instruct，FP16 LoRA，q_proj/v_proj，rank8。
正式实验：1000条训练、100条验证、1个epoch、有效批量8、125次更新；约322.3秒。
训练记录中早期loss约1.40，末段约0.30；最终验证loss约0.3626。
LoRA包含96个张量，B矩阵已有非零更新；adapter文件约2.18MB。
这些证据说明参数真正更新、保存和加载流程已经完成。loss下降本身不证明数学能力提高。

## 同条件测试比较

两次测试使用相同200条题目、参考数值、数据文件哈希、系统提示、贪心生成、192 token生成预算、numeric-v2评分。

|指标|原模型|第一轮SFT|
|---|---:|---:|
|全体样本中自动确认正确|23/200，11.5%|48/200，24.0%|
|答案提取率|74.0%|98.5%|
|可以自动判定的覆盖率|73.0%|97.0%|
|答案/结论冲突|43|0|
|未解析|8|3|
|多问题目待审核|3|3|

逐题配对：14题两者均正确；34题由未确认正确变为正确；9题由正确退化；143题两者均未确认正确。
34题新增正确中，原模型状态为：incorrect20题、conflict11题、unparsed3题。不能把34题全都解释成新增数学能力。
数值正确率增加12.5个百分点，输出一致性和可解析性明显改善。当前仍是短格式解题模型，不能据此声称已具备教学能力。

## 仍存在的限制

48条数值判对中，44条列式计算与参考数值一致，4条不一致：

|ID|模型列式|模型答案|算式实际值|
|---|---|---:|---:|
|test:6096|120/80*100%|150|1.5|
|test:4079|225*(2/5)|135|90|
|test:12372|(545-2*65)/3+65|70|203.333...|
|test:3255|20*(1-(4/5)-(1/2))|6|-6|

“答案对”不保证“推导对”；列式与答案一致也不自动证明方程符合题意。下一轮需单独报告一致性与人工抽检。
当前SFT验证集100题正确17题；原模型只跑过20题验证小样本，不能直接比较它们。应补跑完整100题原模型验证集，再用验证集选择后续实验。
不要不断根据200题测试集调参；后续以验证集迭代，正式报告再做固定测试或新建一套独立题目。
