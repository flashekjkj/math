# 关系解释与计算器模型

## 本轮测试结论

固定200题测试：旧SFT原始48/200=24.0%；旧SFT列式交给计算器95/200=47.5%；新关系说明与工具调用模型42/200=21.0%，工具可执行185/200=92.5%。
新方案在本轮退步，不替换旧版本。自动结构关系说明不等于高质量题意解释，且本轮同时改变提示/目标格式和长度，不能把退步单独归因于某一个因素。
建议目前实用入口为原SFT加计算器：

```bat
python -m math_tutor chat --adapter runs/local-sft-v1 --calculator-only
```

旧SFT工具成绩复用历史生成结果；交互时重新生成不保证逐字一致。新模型测试为合并后FP16、greedy、batch=4；历史生成batch=1，生成条件并非完全相同，不能视为严格的单因素消融。

模型输出三行：关系、列式、工具调用。运行时使用受限AST计算器执行调用，再返回最终答案；不执行任意Python代码，不使用标准答案修补结果。调用格式不合法、多个算式或调用不一致时返回失败。

本轮仍使用原1000题训练、100题验证、200题测试，无算术专项SFT。关系说明由参考算式的运算结构生成，例如“所求量按(a)与(b)的商建立关系”，不是人工核验的语义数量关系解释，不能保证因此改善审题能力。

训练时每个工具调用目标先经过真实计算器验证，SFT只学习关系、列式与工具调用；运行时由程序执行。没有训练一个自主多步工具Agent，也没有让模型学习计算器返回后的二次推理。
