# DPO 效果评测与面试表述

当前结论：现有解释型 DPO 没有显示整体解题收益。验证35%保持不变，历史回归测试34%到32%；测试基线为历史生成，不是同时重跑的严格配对结果。30对偏好集来自原SFT训练池，其中chosen在SFT阶段已经学过；96.7%的TRL reward accuracy只是参考策略校正后的偏好排序诊断，不能解释成解题正确率或相对SFT的独立排序提升。

## 方案一：把当前实验作为有证据的负结果

讲清假设、负例来源、训练更新已发生、逐题改善和退步，再解释为什么排序与生成可能脱节：小数据、chosen已见、生成分布转移、负例覆盖不足、长度和表达风格捷径、数值评分不覆盖题意。它们是待检验假设，不是已经证实的唯一原因。可以说“建立偏好优化与诊断流程，发现未能稳定转化为生成收益”，不能说“显著提升推理”。

## 方案二：先完成可信的排序评测

在完全不参与SFT和DPO的题族上，用同一冻结SFT模型采样多个候选，独立审核解法及参考。冻结这些候选后，让SFT与DPO分别计算同一候选的条件对数概率。报告原始成对排序准确率、每对margin变化、按响应长度分桶的结果及置信区间；如果用长度归一化得分，需单列说明它与训练使用的序列logprob目标不同。

TRL的隐式reward为beta*(log pi_DPO - log pi_reference)，比较的是策略相对reference的变化。不要把它与SFT原始logprob排序混为一个指标；DPO初始化等于reference时reward均为零，初始准确率受平局处理影响，不能用这个基线制造巨大提升。

## 方案三：将偏好目标调整为可测的辅导行为

数学正确率没有改善时，不能只换指标追求好看。应事先声明新的目标并重新构造对应偏好：只要提示时不给最终答案、条件不全时先询问、学生纠正后更新条件、解释具体错误而非附和、闲聊不强套数学模板。

优先使用模型实际生成的候选，审核chosen和rejected。为避免正确性或长度捷径，尽量选择数学内容相同或都正确、主要区别在目标行为的候选；分别保留事实错误和行为错误标签。用户历史必须完全相同，禁止把不同问题的答案组成一对。避免仅把某个数字改错。

## 对照实验

先训练并冻结多轮SFT；之后比较：多轮SFT、相同chosen继续SFT、DPO。控制数据题族、训练token或计算预算，验证集选择超参；独立测试集只用于最终确认。记录至少3个seed，报告配对变化和波动。

主要指标预先固定：提示泄露率、必要澄清率、条件更新正确率、已知错误纠正率、闲聊格式污染率。数学正确率是约束指标，需预设可接受退化范围并结合置信区间，不能只因差异不显著就宣布无退化。解释质量采用匿名成对盲评、交换顺序、允许平局及人工复核。规则命中率只是可自动检查的代理，不能替代语义评价。

## 面试表述模板

“我先验证DPO是否能把正确与错误候选的偏好转化为生成收益。实验中验证正确率未提升，因此没有把它包装成推理增强。进一步分析发现当前偏好集chosen已在SFT出现，排序诊断不能直接代表泛化。我据此设计独立题族的候选排序评测，并把下一阶段偏好目标限定为提示约束、条件更新与错误纠正，用继续SFT对照区分偏好目标和额外监督的作用。”

后半段在真正跑完前应说“设计/计划”，取得结果后才改成“验证”。如果新实验仍无收益，保留失败结论；项目价值来自问题定位、可复现工程和严谨对照，不需要保证每种算法都胜出。
