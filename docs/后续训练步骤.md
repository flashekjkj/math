# 后续训练：按阶段执行

所有命令均在项目根目录执行，Windows使用Anaconda Prompt：

```bat
conda activate math
cd /d E:\desktop\LLM_Project\math-tutor
```

下面只准备了代码与配置，没有替你启动完整第二轮训练。重构验证用的是单独的8条/2步实验，不可与正式成绩比较。

## 阶段A：补齐可信的验证基线（先做）

旧原模型验证只跑20题，SFT验证跑100题，不能直接对比。补跑100题原模型验证：

```bat
python -m math_tutor evaluate --data data/processed/valid.jsonl --output results/base-valid-full.jsonl
```

若该输出名已存在，换一个新的名称，不能覆盖。
比较它与results/sft-valid.summary.json，检查相同题目ID、参考值、提示词、生成长度、评分版本。

从验证集抽查至少30题：10题数值错误、10题冲突/未解析（不足则全部）、10题判对。分别标记列式理解错误、算术错误、单位错误、格式问题。
第一轮SFT有4个答案对但算式不对的测试案例；把这种错误类别用于设计训练任务，不要把这4道测试题原文回流训练。
测试集已经被你查看过，后续避免反复据此选参数；日常只看验证集，最终增加独立新题/新模板题集。

## 阶段B：先做3000条解题数据实验

目的是检查增加数据是否有收益，保持模型、LoRA层、rank、学习率、epoch等参数与第一轮一致。不要一次同时改模型、数据、学习率与训练轮数。

### B1 生成新版本，不覆盖现有第一轮数据

```bat
python -m math_tutor prepare-data --train-size 3000 --valid-size 100 --test-size 200 --output-root data/versions/solve-v2
python -m math_tutor audit --data-root data/versions/solve-v2 --max-length 256
```

读取现有data/raw文件，不重新爬取。查看data/versions/solve-v2/quality_report.json与length_report.json。
按当前固定种子，训练池扩大，原始验证与测试划分规则保持一致；用文件哈希/题目ID核对，评测继续使用原data/processed/valid.jsonl与test.jsonl。
新的prepare使用当前统一提示词，第一轮数据保留了历史旧提示。报告中应记录这点，不声称是完全只改变数据量的严格消融；若要严格控制，可将两轮训练样本system统一后重训控制组。

抽检50～100条，确认方程符合题意，尤其检查百分数、单位、条件不足与多问。对有问题的数据修订来源记录或移除，保存修订清单。
不要只删除训练里难题、保留测试里简单题来抬分。

### B2 检查配置并训练

已准备configs/solve-v2-3k.json，指向新数据与runs/solve-v2-3k，仍从原0.5B Instruct底座开始，避免混淆“增加数据”和“接着训练”的影响。

```bat
python -m math_tutor train --config configs/solve-v2-3k.json --dry-run
python -m math_tutor train --config configs/solve-v2-3k.json --smoke
python -m math_tutor train --config configs/solve-v2-3k.json
```

smoke会写独立带-smoke目录，正式训练不会接着它继续。已有输出目录非空时请改配置中的output_dir，不覆盖旧实验。

### B3 在同一验证集比较

```bat
python -m math_tutor evaluate --adapter runs/solve-v2-3k --data data/processed/valid.jsonl --output results/solve-v2-valid.jsonl
```

比较原模型、第一轮SFT与第二轮SFT，检查数值正确比例、覆盖率、冲突数、式答一致性和人工抽检。
不要仅用训练loss选择模型。可以对checkpoint目录逐个运行验证，在验证集上选取；不是默认“最后一份最好”。
有明确收益再扩到5000条；无收益先改善数据，不马上增加epoch。0.5B的数学能力上限也可能成为瓶颈。

## 阶段C：从解题版升级到诊断/辅导版

这一步才是数学辅导项目的核心。第一轮只有列式与数值，未训练解释和教学策略。

### C1 先手工构建100条高质量诊断样本

限定两类知识点，如百分数与基础方程；每条保存题目、学生步骤、首错位置、错误类型、目标反馈和来源。
输入不包含参考解答、错误类型等标签；这些是训练目标或审核元数据，不能泄漏给模型。

参考examples/curated_records.example.jsonl。模板故意标为reviewed=false：只有你实际检查正确后，才把相应记录设为true。
不要直接把示例两条当正式训练集。正式建立data/curated/tutor-v1.jsonl。

每条结构包含：id、split(train/valid)、task、question、family_id（可省略自动计算）、reviewed、conversations。
为同一道题生成的解答、错例和多轮变体必须共用同一family_id；要在生成衍生数据之前划分家族。
请人工确保语义相同的改写共享家族，自动阿拉伯数字归一化不能识别所有改写。

### C2 再做多轮教学

逐步扩到约1000～2000条/段，起始可用解题40%、诊断30%、辅导30%，同时统计token比例。
可以使用MathDial作为教学结构参考；它是英文、真人教师与模拟学生的交互，不是实际中文学生课堂记录。翻译和生成后必须核验。

生成候选数据时使用这样的约束：

> 给定题目、正确解答和指定学生错误，生成中文辅导对话。教师只能依据当前可见的学生发言，不提前知道尚未透露的内容。只要提示时给一个可执行提示；学生可能答对、答错或部分理解；教师需根据反馈调整。所有教师计算必须正确。不得用“我懂了”机械结束每一段。

先人工检查100～200条，再扩大。外部模型只生成候选，不承担最终正确性认证。
完整解答、只提示、检查作答三种需求都要覆盖，避免模型永远追问或永远不提供答案。

### C3 校验和导出

原prepare-data只处理Math23K解题数据，不会自动生成可信教师对话。人工审核好curated文件后：

```bat
python -m math_tutor.data.build_tasks --input data/curated/tutor-v1.jsonl --output data/versions/tutor-v1 --model models/qwen-0.5b --max-length 512
```

脚本检查角色顺序、审核标记、长度、重复ID、家族跨集合和与已有固定测试题的家族重叠。发现错误只写校验清单，不导出部分可训练集；修正后使用新的输出目录名。
它不检查法律/数学语义，也不自动证明reviewed=true真实有效，审核责任仍是人工。

### C4 开始辅导SFT

configs/tutor-v1.json已准备为512长度；先small smoke测试4GB是否容纳。若OOM，可缩短对话并重新导出长度256的数据，或直接转24GB服务器，不静默截断教师答案。

```bat
python -m math_tutor train --config configs/tutor-v1.json --smoke
python -m math_tutor train --config configs/tutor-v1.json
python -m math_tutor chat --adapter runs/tutor-v1 --system-prompt-file prompts/tutor.txt
```

这里默认从原Instruct底座开始并混入解题样本。如果后续想从第一轮adapter继续，必须明确加载peft_path或先合并权重，同时记录底座与adapter来源；不要误把独立的第二个LoRA当自动叠加了第一个LoRA。

构建独立教学验证情境100～200个，人工盲评：诊断是否准确、提示是否过早泄露、是否响应学生反馈、解释是否正确。数值evaluate不能替代这套教学评价。

## 阶段D：租服务器训练更强模型

先租单张24GB显卡、Linux、至少32GB内存、约60～100GB磁盘的短时实例，实际资源需要随上下文与缓存增长检查。
上传本项目代码、configs、prompts、data和来源记录即可，不上传同级MedicalGPT，也不要复制Windows环境文件夹。

配置Python3.11；PyTorch按服务器驱动/预装镜像选择，安装requirements.txt，再按需安装requirements-advanced.txt。
当前requirements.lock.txt是Windows成功环境快照，用于核对主库版本，不保证所有包可直接在Linux还原。

```bash
python -m math_tutor check
python -m math_tutor download-model --repo-id Qwen/Qwen2.5-7B-Instruct --model models/qwen-7b
python -m math_tutor audit --model models/qwen-7b --max-length 1024
python -m math_tutor train --config configs/server.json --smoke
```

server.json默认仍指原第一版解题数据。正式训练前根据目标把train_file_dir、validation_file_dir换成solve-v2或tutor-v1版本目录，并修改output_dir。先确认输入数据任务与想训练的能力一致。
采用7B、4bit QLoRA、BF16，需要bitsandbytes与支持BF16的GPU。先测显存，再跑正式训练。
换7B必须重新训练；0.5B adapter不能加载到7B。先测试7B原模型作为基线，再测试其SFT版本。

## 阶段E：有明确失败案例后再做DPO

SFT完成并有可靠验证后，构建200～500个偏好对起步，逐步扩展。chosen与rejected要在相同历史下比较。
对比类型：正确/错误诊断、提示恰当/直接泄题、合理澄清/编造条件、算式与答案一致/不一致。
不要一律偏好更长、语气更好或某个教师模型生成的答案。

数据格式：

```json
{"conversations":[{"from":"human","value":"题目和学生作答。只提示我下一步。"}],"chosen":"经过核验的恰当提示","rejected":"经过核验的不恰当回应"}
```

独立保存data/versions/preference-v1/train与valid，按题目家族隔离，不复用测试题。
在服务器上将最佳SFT adapter合并到对应原底座：

```bash
python -m math_tutor.tools.merge_peft_adapter --base_model models/qwen-7b --lora_model runs/server-sft-v1 --output_dir models/math-sft-7b
python -m math_tutor.training.dpo_training --help
```

合并目录不能覆盖原模型，合并前后用相同输入检查生成；合并需要额外CPU/GPU内存。
DPO用合并后的SFT作为model_name_or_path，use_peft=true、qlora=true、load_in_4bit=true，学习率从5e-6～1e-5、短步数开始。参数以本地dpo模块--help为准，不能直接照抄SFT配置。
使用入口：python -m math_tutor train --stage dpo --config configs/你的DPO配置.json。
比较SFT与DPO的数学正确性和教学行为；没有收益或明显退化就保留SFT，不为了凑流程强行上线DPO。

GRPO、PT、PPO、OPD等源码已本地化，但不属于当前必做路线。它们的help检查不代表实际训练与显存已验证，不建议在4GB上作为下一步。

## 阶段完成标准

- A：补齐同条件验证基线，人工审查评分与题目质量。
- B：有版本化3k实验与对照，不只比较loss。
- C：有可追溯、人工核验的诊断/教学数据及教学验证。
- D：有7B原模型和7B SFT同条件对照。
- E：偏好优化能解决实际观察到的问题，并有回归验证。

最终报告写实际数据规模、实验条件、提升及退化，不把脚本运行成功或loss降低等同于数学辅导效果。
